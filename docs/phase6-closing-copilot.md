# Phase 6 — Closing Copilot (월마감) 설계

## 1. 목표

월마감 담당자가 한 화면에서 **이번 달 숫자가 왜 이렇게 나왔는지**와 **마감 전에 남은 일**을 확인하게 한다.

- 월별 집계(매출·비용·영업이익, 계정과목별, 거래처별), **전월 대비·전년 동월 대비**, **주요 변동 탐지**는 모두 DB 집계와 규칙으로 계산한다.
- LLM은 계산된 집계 결과(facts)만 받아 문장으로 설명한다. 원본 전표는 보내지 않는다. (Phase 5 설명 구조 재사용)
- 마감 체크리스트(미처리 증빙·미대사 은행 거래·미검토 이상거래 등)로 **마감 진행률**을 보여주고, 사람이 **마감 확정**한다.

## 2. 집계 기준

| 항목 | 계산 |
|---|---|
| 대상 전표 | 취소(VOID)되지 않은 전표, 전표일(`entry_date`)이 해당 월 |
| 매출 | 수익(REVENUE) 계정 라인의 대변 − 차변 |
| 비용 | 비용(EXPENSE) 계정 라인의 차변 − 대변 |
| 영업이익 | 매출 − 비용 (간이: 영업외 손익을 따로 구분하지 않는다) |
| 계정과목별 | 수익·비용 계정별 같은 방식 |
| 거래처별 비용 | 비용 라인의 거래처 = 연결 거래의 거래처 → 연결 증빙의 공급자 → 확정 대사된 은행 거래의 거래처 순. 없으면 "(거래처 미상)" |
| 부서별 | 현재 데이터 모델에 부서가 없어 제공하지 않는다 |

금액은 `BigDecimal`로 계산하고, 증감률은 비교값이 0이면 계산하지 않는다(null, "신규").

## 3. 주요 변동 탐지 (`VarianceDetector`, 순수 클래스)

비교 기준: 전월(`PREV_MONTH`), 전년 동월(`PREV_YEAR`). 대상: 합계(매출·비용·영업이익), 계정과목, 거래처(비용).

| 코드 | 조건 |
|---|---|
| `INCREASE` / `DECREASE` | \|증감액\| ≥ 1,000,000원 **그리고** \|증감률\| ≥ 30% |
| `NEW` | 비교값 0, 당월 ≥ 1,000,000원 |
| `GONE` | 당월 0, 비교값 ≥ 1,000,000원 |

증감액이 큰 순으로 정렬해 상위 10개를 "주요 변동"으로 보여준다. 각 변동에는 사람이 읽는 사유 문장을 붙인다.

## 4. 마감 체크리스트 (규칙)

| 코드 | 완료 조건 (해당 월) |
|---|---|
| `DOCUMENTS_REVIEWED` | 처리되지 않은 증빙(처리 중·확인 필요·검토 완료·실패)이 없음 (증빙 거래일 기준) |
| `DOCUMENTS_POSTED` | 승인된 증빙 중 전표가 없는 것이 없음 |
| `TRANSACTIONS_POSTED` | 취소되지 않은 거래 중 전표가 연결되지 않은 것이 없음 |
| `BANK_RECONCILED` | 은행 거래가 모두 확정 대사됨 |
| `ANOMALY_SCANNED` | 이상거래 분석 기간이 해당 월 전체를 포함한 적이 있음 |
| `ANOMALIES_REVIEWED` | 검토 대기(OPEN) 이상거래가 없음 |

진행률 = 완료 항목 수 / 전체. 각 항목은 남은 건수와 해당 화면 링크를 가진다.

## 5. 마감 확정

- ADMIN이 의견과 함께 **마감 확정**하면 그 시점의 집계·체크리스트 스냅샷을 저장한다. 체크리스트가 남아 있어도 확정할 수 있지만, 미완료 항목은 스냅샷과 Audit Log에 남는다.
- **마감 취소**(다시 열기)도 ADMIN이 사유와 함께 할 수 있다.
- 이번 Phase에서는 마감된 월의 전표 수정을 막지 않는다(기간 잠금은 범위 밖). 화면에서 마감 이후 숫자가 바뀌었으면 "확정 이후 변경됨"을 표시한다.

## 6. LLM 설명

- 대상 `CLOSING_MONTH`, 대상 ID는 `closing_months.id`(회사·월마다 한 행).
- facts: 기준월, 매출·비용·영업이익(당월·전월·전년 동월·증감액·증감률·방향), 주요 변동 상위 항목, 이상거래 현황, 남은 체크리스트 항목. 금액·증감률·방향은 모두 Spring이 계산해 표시 형식으로 넣는다.
- 집계는 수시로 바뀌므로 자동 생성하지 않고 **사람이 "설명 생성"을 누를 때** 요청한다. 근거가 같으면 다시 만들지 않는다.

## 7. Entity — `ClosingMonth`

`(company, month)` 유일. `status`(OPEN / CLOSED), 확정자·시각·의견, `snapshot` JSONB(확정 시 집계·체크리스트), 생성 시각.

## 8. API

| Method | Path | 설명 |
|---|---|---|
| GET | `/companies/{cid}/closing/{yyyy-MM}` | 월마감 보고서 (집계·비교·주요 변동·체크리스트·이상거래 현황·확정 상태·설명) |
| GET | `/companies/{cid}/closing/trend?to=yyyy-MM&months=12` | 월별 매출·비용·영업이익 추이 |
| POST | `/companies/{cid}/closing/{yyyy-MM}/explanation` | 설명 생성·다시 생성 |
| PUT | `/companies/{cid}/closing/{yyyy-MM}/explanation` | 설명 수정 (Audit) |
| POST | `/companies/{cid}/closing/{yyyy-MM}/close` `{note}` | 마감 확정 (ADMIN) |
| POST | `/companies/{cid}/closing/{yyyy-MM}/reopen` `{note}` | 마감 취소 (ADMIN) |

권한: 조회는 모든 멤버, 설명 생성·수정은 ADMIN·ACCOUNTANT, 마감 확정·취소는 ADMIN.

## 9. AI 서비스 (월마감 설명)

- 프롬프트 `closing-v1`: 손익 요약 → 주요 변동 상위 2~3개 → 검토 대기 이상거래 → 체크리스트 순으로 3~5문장. 변동의 원인은 추측하지 않고 "확인이 필요합니다"로 쓴다.
- 출력 검증은 Phase 5 규칙(근거 밖 숫자, 단정 표현, 외국 문자, 길이)에 **증감 방향 검증**을 더한다. 문장을 합계 이름(매출·비용·영업이익, 다른 낱말 안에 든 것은 제외)마다 끊고, 한 조각에 비교 기준(전월 또는 전년)이 하나만 있는데 근거와 반대 방향 낱말만 있으면 거부한다. 애매하면 통과시킨다.
- 실패하면 근거 문장을 그대로 옮긴 템플릿 설명(FALLBACK)을 쓴다. 템플릿도 같은 검증을 통과한다.

## 10. 화면

- `월마감` 메뉴 (`/c/{cid}/closing?month=yyyy-MM`, 기본은 지난 달). 월 이동, 합계 카드 3개(전월·전년 동월 대비), 12개월 매출·비용 추이(선 2개, 툴팁에 영업이익, 표로 보기, 월을 누르면 이동), 체크리스트와 진행률(항목을 누르면 해당 화면), AI 월마감 설명(생성·수정·다시 생성), 마감 확정·취소(ADMIN, 의견 필수, 남은 항목 경고, 확정 이후 변경 경고), 주요 변동, 계정과목별·거래처별 표.
- Dashboard의 "월마감 진행률"은 지난 달 기준이다.
